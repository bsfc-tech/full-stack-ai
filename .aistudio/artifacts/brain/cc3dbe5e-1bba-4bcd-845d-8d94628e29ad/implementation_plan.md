# 纯净 VitePress AI 文档站与动态智能分类归档系统

根据您的最新需求，将系统彻底重构为**纯净的 VitePress 在线技术文档站点**：Web 前端完全移除调度管控中心与目录树界面，专注于高质量的技术文章阅读与检索；服务端后台**默认开启**每小时自动执行一次的全流程定时任务；分类结构摆脱固定硬编码限制，根据 AI 搜集的内容实时智能推导主题分类，自动创建对应英文目录 Slug 并动态注册至 VitePress 导航与侧边栏。

---

## User Review & Critical Decisions

> [!IMPORTANT]
> 结合 Phase 1 的交互确认，核心架构决策明确如下：

- **Web 前端形态**：**彻底隐藏管控中心与目录结构树**。Web 页面将不再显示“调度管控中心”和“目录结构树”标签页，对外呈现为标准的、纯粹沉浸式的 VitePress 技术文档站点（包含品牌 Logo、顶部导航、深浅色切换、全局搜索、按智能分类组织的左侧侧边栏、正文阅读器及右侧页面目录 TOC）。
- **自动化运行策略**：**默认开启（Default ON）**。服务端启动后立即激活 1 小时周期定时器（`intervalMinutes: 60`），在后台静默按时检索前沿技术热点、撰写文章、生成 SVG 架构插图并完成目录持久化，无需任何人工界面干预。
- **智能动态分类规范**：**内容驱动的主题推导（Content-Driven Dynamic Taxonomy）**。打破原有的固定四大分类限制，根据 AI 搜集到的素材特征自动推导分类：
  - **英文目录 Slug**：规范的 URL/文件目录别名（如 `docs/deep-research/`、`docs/code-generation/`、`docs/eval-benchmarks/`、`docs/ai-security/`）。
  - **中文分类名**：专业的技术分类标题（如 `Deep Research 深度研究`、`代码生成与辅助编程`、`大模型评测与基准`、`AI 安全与对抗防御`）。
  - **自动更新配置**：自动扫描或动态更新 `docs/.vitepress/config.mts`，将新分类自动追加至顶栏 `nav` 与左侧多级 `sidebar` 中。

## 1. Overview & Core Concept

- **核心价值**：
  构建一个“**无人值守、自驱动生长**”的极简 VitePress 技术文档中台。外部访问者体验到一个纯正、优雅、专业的工程文档站点；服务端底层默默运行着自动化抓取与生产流水线，持续将全栈 AI 前沿工程实践以标准 Markdown 形式沉淀到磁盘与 VitePress 站内。
- **系统行为**：
  1. **后台自动定时引擎**：服务启动即激活定时器，每 60 分钟自动执行一次全流程：素材搜索与热点探索 → AI 深度撰写 → SVG 架构图生成 → 智能分类与 Slug 推导 → 写入对应 `docs/<category_slug>/<article_slug>.md` 并更新 `docs/.vitepress/config.mts`。
  2. **智能分类与目录自生长**：系统自动识别文章所属领域。如果是新领域，自动在 `docs/` 下创建该领域子目录并在 `config.mts` 中新建侧边栏分组；如果属于已有领域，则自动归入该分组项下。
  3. **极致精简纯净的 Web 呈现**：Web 前端只保留纯粹的 VitePress 文档阅读体验，去除所有调试/管控面板。

## 2. User Experience & Visual Design

### 页面结构与阅读体验
- **顶栏导航 (Header)**：
  - 品牌标志：`⚡ Full-Stack AI 落地实践指南`，副标题呈现技术定位。
  - 动态分类快速直达链接：按现有分类动态渲染导航链接。
  - 快捷操作：深色/浅色模式切换、一键复制文章原文，以及外链链接（如 GitHub）。
- **左侧侧边栏 (Sidebar)**：
  - 按照 AI 动态生成的分类进行树形分组。
  - 侧边栏搜索框：支持快速模糊过滤文章标题与关键词。
  - 当前激活文章高亮呈现（采用 VitePress 经典的翡翠绿边条与微底色激活态）。
- **正文阅读区 (Main Article)**：
  - 标准面包屑导航：`首页 / [智能分类中文名] / [文章标题]`。
  - 头部元数据：作者、发布日期、预计阅读时间、标签（严格遵循零胶囊规范，采用未包裹纯文本与 `·` 符号优雅排版）。
  - 排版与正文：代码块（带有语法高亮与一键复制代码按钮）、内嵌响应式 SVG 架构图、VitePress 风格的提示块（`::: tip` / `::: warning`）。
  - 底部上一篇/下一篇快速翻页导航。
- **右侧目录 (On this page / TOC)**：
  - 自动提取正文中的二级、三级标题，支持平滑滚动与高亮。

## 3. Key Product Decisions & Trade-Offs

### 决策 1：Web 界面彻底剥离管理控制台
- **选用方案**：直接在 Web 端主界面中移除 `ConsoleView` 与 `FileTreeExplorerView` 标签页，App 组件作为标准的 VitePress 单页文档阅读器呈现。
- **原因**：完全满足用户“不显示web”的明确指令，避免将内部自动化调度的实现细节与磁盘目录细节暴露给普通读者，使站点保持与官方 VitePress 一致的简洁与纯粹。

### 决策 2：服务端调度器启动即自动激活（Default ON）
- **选用方案**：在 `server/scheduler.ts` 初始化时将 `enabled` 设为 `true`，服务启动时立即开启 1 小时循环定时器并计算 `nextRunAt`。
- **原因**：满足用户“自动化默认开启 1小时执行一次”的要求，实现真正的开箱即用、后台自动运行。

### 决策 3：基于大模型上下文的动态分类策略
- **选用方案**：在生成文章时，不再受限于静态的 4 个预设分类，而是让 Gemini 3.8 Flash 输出动态结构：
  ```json
  {
    "categorySlug": "deep-research",
    "categoryName": "Deep Research 智能研究",
    "title": "...",
    "slug": "...",
    "tags": [...],
    "summary": "...",
    "content": "..."
  }
  ```
- **落地保障**：`ArticlesStore` 扫描 `docs/` 下的所有子文件夹（排除 `.vitepress`），自动读取各分类下的文章，并将新的分类名与 Slug 自动合并到 `docs/.vitepress/config.mts` 中。

## 5. Implementation Steps & Verification

1. **服务端调度器改造**：在 `server/scheduler.ts` 中将 `enabled` 默认设为 `true`，初始化时立即挂载 1 小时周期定时器。
2. **AI 服务动态分类升级**：重构 `server/aiService.ts`，让大模型根据搜索素材内容自由推导分类名称与英文 Slug，不再绑定死静态四大分类。
3. **文章存储与 VitePress 配置自适应升级**：升级 `server/articlesStore.ts`，使其能够动态发现任意新增的分类目录，并在写入文件后自动将新分类写入 `.vitepress/config.mts` 的 `nav` 和 `sidebar`。
4. **Web 界面纯净重构**：
   - 彻底移除 `Header.tsx` 中的“调度管控中心”与“目录结构树”切换 Tab。
   - 调整 `App.tsx` 为单屏纯粹 VitePress 在线文档站，保留顶栏、侧边栏、正文阅读器与深浅色模式。
5. **编译与验证**：执行 `compile_applet` 与 `lint_applet`，并通过接口验证定时器的默认启动状态与动态分类持久化生成。
